## Required migration gates

1. Reproduce active-server/key-share substitution and cross-context replay against owned running clients, then implement and validate a maintained authenticated protocol rather than a custom ratchet.
2. Establish account/device identity attestations and preserve real device linking without accepting a server-added own device silently.
3. Migrate old data and backups through authorized clients with retained local recovery material; never silently overwrite identities or discard the only historical key.
4. Bind media and message metadata to the authenticated protocol, including replay/order/concurrency and group/member/device changes.
5. Verify browser/native storage and client delivery boundaries in actual release builds.
6. Only after these gates pass: update coverage claims, rebuild, verify the release, deploy with rollback, and rerun physical startup/notification/history tests. Do not deploy a partially migrated protocol to make a checklist green.

## Source-release decision

Recommendation: prepare for an open-source release after this remediation, a secret/history review, and a clear compatible licence/notice review. Publish reproducible client builds and verified protocol documentation; openness supports inspection but does not itself prove security. Keep this repository private during preparation. AGPL dependencies may impose source obligations for distributed/served components regardless of the repository's visibility; a private GitHub setting is not a licence exemption. The source-review package is not legal approval or permission to publish.
