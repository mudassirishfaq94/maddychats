# Circlo Google Play / Trusted Web Activity readiness

Audit date: 16 October 2026. Baseline: `ca68422a7d6552d1557a65cb117104d7d5cf9abc`, also the remote `main` head at inspection. **Decision: NOT READY for a Play release.** The web application is a viable TWA foundation; an installable, signed, verified TWA release and its operational compliance have not been established. Approval is never guaranteed.

This is the first deliverable, completed before application changes. Subsequent phases must have separate commits and evidence. No GitHub push, Play upload, paid service, production configuration change, or production account mutation is authorized by this audit.

## Evidence boundaries and method

- Inventoried all 771 tracked paths: 117 API route files, 32 page files, 63 existing Android files. Reviewed architecture, security boundaries and release-critical paths; this is not proof that every line or every feature is defect-free.
- Inspected the local Next 16.3.8 manifest documentation before planning changes. Read manifest, service worker, offline document, CSP, authentication/device recovery, privacy/deletion/reporting, realtime, encryption/key storage, upload/storage and existing Android implementation.
- Fresh public HTTPS GETs and an isolated Playwright Chromium mobile-sized context at 10:04 UTC. No user account, real chat or load test used. Registered the existing worker in that disposable context, switched it offline and clicked Retry. See `readiness-evidence-2026-10-16.json`.
- Fresh unit suite: **65 passed, 0 failed**. These cover input validation, passwords, auth/device recovery, crypto/cache, notifications, media, deployment security and other regressions; they are not an Android device test or a new complete integration run.
- Fresh Gitleaks full reachable history: **372 commits, approximately 7 MB scanned, exit 0** with the existing seven exact reviewed exclusions. These exclusions cover disposable test credentials, a Cargo checksum and Firebase public client configuration. This is not a claim that no secret can exist or that historical credentials were never exposed.
- Remote main was compared read-only with `git ls-remote`. Prior CI evidence exists for this baseline, but was not substituted for fresh Android testing. No production backend authentication, real email delivery, push delivery, microphone recording, destructive deletion or live encryption exchange was performed in this phase.
- `java`, `adb`, `bubblewrap` and `gitleaks` were not on PATH. A pre-existing local Gitleaks executable was available and used. No emulator/physical Android or Play Console session was available. A generated/compiled TWA and Play pre-launch report remain unverified.

**PASS** means the explicitly stated check has supporting evidence, not blanket compliance. **FAIL** means a demonstrated defect or missing release artifact. **NOT VERIFIED** means source evidence alone is insufficient, environment/access is unavailable, or an owner decision is needed. P0 blocks packaging/release, P1 blocks a dependable release, P2 improves maintenance or presentation.

## Precise implementation and verification plan

1. **Phase1 — this report and sanitized evidence.** Commit separately; preserve baseline findings and limitations. No app behavior changes. Done when report, code locations, live observations and release gates are reviewable.
2. **Phase2 — verified offline defect and Git guardrails only.** Replace blocked inline Retry with a script-free same-origin form, version the offline cache, test actual worker fallback with enforced CSP while offline and after reconnect. 6. **Phase6 — acceptance and release gate.** Two fake-data users on physical Android phones; API24/older supported floor, Android13 permission changes and Android16 target behavior; Chrome stable plus an alternative TWA provider/fallback. 7. **Release remains manual and separately authorized.** Owner completes Console forms, reusable reviewer access, rating, testing eligibility and Play pre-launch review. Internal/closed upload and final publication each require approval. No automatic approval guarantee.

### Minimal Android permission policy for the proposed TWA

Use INTERNET and generated verified TWA delegation components. Enable notification delegation, inspect resulting Android13+ permission behavior. Microphone/camera access should remain browser-origin permission prompts at the moment of use; use system file picker without broad media/storage access. Do not copy RECEIVE_BOOT_COMPLETED, READ_MEDIA_*, biometric, native FCM, full-screen call intent, background microphone or foreground-service permissions merely because the legacy app has them. Add a permission only after an actual functionality test demonstrates need and its policy implications are reviewed.

### Stop conditions requiring evidence or owner input

- Existing Play package/listing and signing continuity unknown.
- No final app-signing fingerprint, no verified DAL, no compiled TWA or physical-device evidence.
- Public support/deletion contact, moderation/child-safety operations and reusable reviewer access not confirmed.
- No Play Console forms, content rating or testing eligibility verified.

These are explicit blockers, not reasons to bypass trust, pretend a native wrapper improves cryptography, or claim the release is complete.
