# Admin and 404 repair

- Added an application-themed missing-page screen with homepage/chat navigation. Unknown routes retain HTTP 404 and Next's automatic noindex behavior.
- `/admin` and its subpaths temporarily redirect to the real `/app/admin` routes. The alias is noindex and uses the same private authorization checks.
- Admin/moderator accounts without enrolled two-step verification now receive setup instructions and a deep link that opens the correct Profile disclosure. They do not receive privileged page content; admin APIs still reject access until MFA is enabled and sign-in requirements are met.
- Unauthenticated access goes to sign-in. Signed-in ordinary accounts receive an access-required explanation without the privileged shell; admin APIs remain forbidden. Knowing an email or URL does not grant an administrator role.
- Overview, storage, audit and security reads now check HTTP status, use private/no-store requests, time out, cancel on unmount and offer retry/re-authentication. API error envelopes cannot become dashboard state.
- Messages and activity reads now reject unsuccessful responses and display retry controls. Missing navigation links to those two sections were restored. Mobile navigation buttons use 44-pixel touch targets.

Local browser regression covers eight admin routes, four simulated 503/retry flows, and MFA gating without the admin shell. Existing tests retain ordinary-user denial, stale authentication, CSRF, role checks, immutable audit, and revocation. Public crawling checks the real 404 screen at 320/390/1280 pixels and both navigation destinations.

Production account inspection found that the previously identified owner email currently has role `user` and no enrolled MFA. This is account authorization state, not an administrator-page rendering defect. This release does not promote a production account, disable MFA, or introduce email-based administrator access. A deliberate administrator assignment and MFA setup are required for that account to use the dashboard.
